// =========================================================== Synopsis
== Synopsis
[verse]
// tag::synopsis[]
aerospace lock [-h|--help] [--window-id <window-id>]
aerospace lock [-h|--help] [--window-id <window-id>] [--fail-if-noop] on
aerospace lock [-h|--help] [--window-id <window-id>] [--fail-if-noop] off

// end::synopsis[]

// =========================================================== Description
== Description

// tag::body[]
{manpurpose}

Commands that would move, resize, re-layout, close or stash a locked window fail instead:
`move`, `swap`, `resize`, `move-node-to-workspace`, `move-node-to-monitor`, `join-with`, `split`, `layout`,
`fullscreen`, `macos-native-fullscreen`, `macos-native-minimize`, `close`, `scratchpad stash`.
`close-all-windows-but-current` skips locked windows.

A locked floating window is pinned to the frame it had when it was locked.
Mouse drags and resizes initiated by the app snap back.
A locked tiled window can't be manipulated directly, but its tile still adapts when its neighbours change.
A locked sticky window keeps following the visible workspace with a fixed frame.

The window's own close button isn't affected (macOS doesn't allow intercepting it).
Without an argument, the lock state is toggled.
